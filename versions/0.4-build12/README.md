# Orchard 🍎 0.4 — build12

Expand the ZIP once. Open **Orchard.app** in `Orchard/`; guides and notices are in **はじめに・説明書**.
[Illustrated installation](INSTALL.md) / [Update continuity](UPDATE.md) / [Guide](GUIDE.md) / [Changes and acceptance status](RELEASE_NOTES.md).

Static suspicious-instruction rules and SHA-256 matching are separate checks. The stored 300,000 unique values retain all previous 100,000 and add 200,000. They are neither the latest 300,000 nor the whole corpus. Matches and nonmatches are investigative leads, not safety/danger verdicts or permission to execute. See [data sources](DATA_SOURCES.md).

Age alone does not stop matching. Dates and scope remain visible; corruption, incomplete inspection, withdrawal and other integrity holds remain. Automatic updates are OFF.

A local development folder can be registered without GitHub or an existing supported MD file. New supported files can be detected while monitoring. Registration is limited to one folder and monitoring starts manually. Continuous monitoring and prevention of all AI writes are not guaranteed. Updates validate the previous registration and retained evidence, then reference compatible existing state. Active older monitoring or invalid state produces an explained hold rather than silently resetting registration.

Apple Silicon/macOS26+. Bundled Python/SQLite, ad-hoc signed, not Apple-notarized. App-specific approval is not a safety guarantee.
Software is MIT; data has separate abuse.ch/Spamhaus consent for a free, noncommercial OSS Orchard subset. No standalone data redistribution, commercial use or AI training/customization. Keep [license scope](LICENSE_SCOPE.md) and [notices](THIRD_PARTY_NOTICES.md).
