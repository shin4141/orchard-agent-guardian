# 更新と監視登録の引き継ぎ — build12

先に [検証状況](RELEASE_NOTES.md) を確認してください。使い捨てr2相当状態で、未確認0件・1件の引き継ぎと変更レビューを確認しました。実利用者の登録を試験で切り替えたものではありません。旧アプリと登録データを保持し、更新だけを理由に削除しないでください。

1. 旧Orchardで監視を停止し、アプリを正常終了します。未確認変更は承認せず残せます。
2. build12はユーザー共通の `~/Library/Application Support/Orchard/registration.json` を登録入口にします。互換性を確認できる公開r2の `Private100KCandidate7/registration.json` があれば、元の `state_dir` を参照する入口を作ります。baseline、pending、承認履歴の移動・削除・自動承認は行いません。
3. build11の `Private300KCandidate11` だけに登録がある場合は、自動選択せず「別の登録を確認」でフォルダと未確認件数を確認してから引き継ぎます。r2とbuild11の記録は統合しません。r2の不正な登録を無視してbuild11へ切り替えることもありません。
4. 監視フォルダ・未確認件数を読みます。登録後も監視は停止中です。手動で「監視を開始」を選びます。ログイン時起動はありません。

旧監視のロック、保存中の状態、壊れたJSON、rootの不一致、未確認記録の欠落、承認処理の中断などは理由付き保留になります。「未登録」へ黙って初期化しません。旧版の処理を終了した後に「登録を再確認」を使ってください。原本や保存先を手作業で消すと未確認証拠を失うため、破損時は [問い合わせ](SUPPORT.md) へ進みます。

新しい入口があっても、実データは旧 `Private100KCandidate7` や確認したbuild11の保存先に残る場合があります。古い名前だけを理由に削除しないでください。[戻す方法](ROLLBACK.md) / [停止・削除](UNINSTALL.md)。

## 登録検証が時間切れになった場合

登録検証が時間切れになっても、既存の登録・信頼基準・未確認変更・承認履歴は保持されます。監視登録の確認は保留になりますが、「ZIPを選んで照合」からZIP検査は引き続き利用できます。ZIP検査自身の整合性異常・検査不能などによる保留は別です。

「登録を再確認」を選ぶか、Orchardを正常終了して再起動してください。登録ファイルや保存先を削除・初期化する必要はありません。再発する場合は、画面の時間切れメッセージにある括弧内の段階名（例: `READER_IMPORT`、`START_UNKNOWN`）と、build番号・macOSのバージョンを添えて [問い合わせ](SUPPORT.md) へ報告してください。登録JSON、監視原文・差分、秘密情報を公開Issueへ添付しないでください。

先行試行の時間切れ原因は未確定です。再確認や再起動で必ず解消するとは保証しません。
